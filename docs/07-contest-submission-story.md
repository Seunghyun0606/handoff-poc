# 07. 공모전 제출용 스토리

## 제목 후보

**이 문서만 받고 내일부터 혼자 일할 수 있을까요? — AI 인수인계 구멍 탐지기**

## 한 줄 소개

인수인계 문서를 요약하는 AI가 아니라, **새 담당자가 실제로 업무를 수행하기 위해 빠진 정보가 무엇인지 찾아 질문해주는 AI 리뷰어**입니다.

## 1. 문제 정의

인수인계 문서는 보통 작성자 관점에서 만들어집니다.

작성자에게 너무 익숙한 정보는 자연스럽게 빠집니다.

- 어느 시스템의 어느 메뉴에서 실행하는지
- 어떤 권한이 필요한지
- 몇 시까지 끝내야 하는지
- 결과가 정상인지 어떻게 검증하는지
- 오류가 나면 어디까지 재시도하고 누구에게 연락하는지

문서에는 업무 설명이 있지만, 새 담당자는 실제 업무를 시작하면서 다시 질문해야 합니다.

기존 생성형 AI로 문서를 요약하면 **이미 적혀 있는 내용은 더 짧아지지만, 애초에 적혀 있지 않은 정보는 발견하기 어렵습니다.**

## 2. 아이디어

질문을 바꿨습니다.

`이 문서의 핵심 내용은 무엇인가?`가 아니라,

> **`이 문서만 받고 내일부터 혼자 일할 수 있는가?`**

AI는 인수자의 관점에서 문서를 다음 12개 영역으로 점검합니다.

1. 업무 목적
2. 실행 절차
3. 시스템/도구
4. 계정/권한
5. 담당자/연락처
6. 수행 주기/마감
7. 입력 데이터
8. 출력 결과
9. 예외 처리
10. 장애 대응
11. 검증 방법
12. 후속 업무

각 항목을 `CLEAR / PARTIAL / MISSING`으로 판단하고, 단순 지적에서 끝나지 않고 **작성자에게 다시 물어봐야 할 질문**으로 변환합니다.

## 3. 사용 흐름

### Step 1. 문서 입력

사용자는 기존 인수인계 문서를 붙여넣거나 `.txt`, `.md` 파일을 올립니다.

### Step 2. AI 분석

약 10초 내외의 분석 후 다음을 보여줍니다.

- 전체 Readiness Score
- 12개 영역별 상태
- Critical Gap
- 확인이 필요한 질문

### Step 3. 질문으로 빈칸 확인

예를 들어 문서에 `오류가 나면 담당자에게 문의한다`라고만 적혀 있다면 AI는 다음을 묻습니다.

- 누구에게 연락해야 하는가?
- 연락 채널은 무엇인가?
- 먼저 재시도해야 하는가?
- 재시도 후에도 실패하면 어디까지 에스컬레이션하는가?

### Step 4. 개선 문서 생성

AI는 없는 사실을 만들어내지 않습니다.

확인되지 않은 값은 다음처럼 남깁니다.

- `[정보 필요]`
- `[권한 확인 필요]`
- `[담당자 확인 필요]`
- `[시간 확인 필요]`

따라서 AI가 그럴듯한 인수인계 문서를 창작하는 것이 아니라, **사람이 확인해야 할 빈칸이 보이는 작업 문서**를 만듭니다.

## 4. 실제 동작 PoC

- Web: Next.js / TypeScript
- Deployment: Vercel
- LLM: Azure OpenAI
- DB / 로그인 없음
- 실제 Production URL에서 동작
- Azure 장애나 API 미설정 시 Demo fallback 지원

PoC URL: `https://handoff-poc.vercel.app`

## 5. 검증 방법

실제 업무 문서를 확보하기 전, 서로 다른 8개 업무의 Synthetic 인수인계 문서를 만들었습니다.

문서 작성 단계에서 먼저 `POOR / FAIR / GOOD` 등급과 의도적으로 빠뜨린 항목을 고정한 뒤, 현재 Production AI에 입력했습니다.

도메인:

- 매출자료 공유
- 급여 인터페이스
- 신규 계정 발급
- SSL 인증서 갱신
- 신규 입사자 온보딩
- 야간 배치 모니터링
- 협력사 세금계산서
- DB 백업 복구 점검

## 6. 검증 결과

### 핵심 숫자

- Azure 실제 호출 성공: **8/8 (100%)**
- Human grade ↔ AI Score band 일치: **75%**
- 의도적으로 심은 Gap 탐지 Recall: **77.8%**
- Critical Gap Recall: **92.3%**
- 생성 질문: **33개**
- 합성 문서 단일 검토 기준 실행에 유용한 질문: **33/33**
- 평균 초기 분석 시간: **11.5초**

등급별 평균 AI Score:

| Human grade | 평균 AI Score |
| --- | ---: |
| POOR | 34 |
| FAIR | 63 |
| GOOD | 95 |

개별 점수 오차는 있었지만 문서 품질군은 평균적으로 명확하게 분리되었습니다.

## 7. 대표 사례

### Before

> 매일 오전 매출 자료를 다운받아서 팀에 공유한다. 월말에는 정산 자료도 추가로 만든다. 파일에 문제가 있거나 화면 오류가 나면 담당자에게 문의한다.

이 문장은 사람에게는 익숙해 보이지만 새 담당자는 바로 일을 시작할 수 없습니다.

### AI 분석

- Score: **31**
- Gap: **10개**
- 질문: **8개**

AI가 만든 질문 예시:

> 업무 수행에 필요한 계정·권한은 무엇이며, 권한이 없을 때 누구에게 어떤 방식으로 신청합니까?

> 다운로드한 매출 자료와 월말 정산 자료가 정상인지 무엇과 어떤 기준으로 확인해야 합니까?

> 다운로드나 화면 오류가 발생했을 때 재시도·우회 방법과 문의가 해결되지 않을 경우의 에스컬레이션 절차는 무엇입니까?

### After

AI 개선 문서는 없는 정보를 임의 생성하지 않고 다음과 같은 빈칸을 만들었습니다.

- 매출 자료 다운로드 시스템: `[정보 필요]`
- 필요한 계정 및 권한: `[권한 확인 필요]`
- 완료 마감: `[시간 확인 필요]`
- 문의 담당자: `[담당자 확인 필요]`
- 정상 여부 검증 기준: `[정보 필요]`

이제 인계자는 **무엇을 더 작성해야 하는지** 알 수 있습니다.

## 8. 차별점

### 기존 방식

`긴 문서 → AI → 짧은 요약`

### 제안 방식

`불완전한 문서 → AI → 빠진 정보 → 확인 질문 → 보완된 문서`

핵심 차이는 AI가 **존재하는 정보를 압축하는 것이 아니라 존재하지 않는 정보를 표면화한다는 것**입니다.

## 9. 기대 효과

### 인계자

- 무엇을 더 써야 할지 체크 가능
- 자신의 암묵지가 어디에서 생략됐는지 발견

### 인수자

- 업무 시작 후 반복 질문 감소
- 장애/예외 상황에서 멈추는 위험 감소

### 조직

- 문서 품질을 사람의 작성 습관에만 의존하지 않음
- 업무 변경, 퇴사, 조직 이동 시 지식 손실 감소
- SOP, 운영 매뉴얼, 교대근무, 외주 업무 등으로 확장 가능

## 10. 검증에서 발견한 한계까지 공개

Synthetic Validation에서 AI가 놓친 Critical Gap이 1건 있었습니다.

또한 Human grade가 FAIR인 문서 두 건은 AI Score가 각각 95와 39로 크게 벗어났습니다.

그래서 이 서비스는 현재 단계에서 `절대적인 문서 품질 점수기`라고 주장하지 않습니다.

오히려 테스트에서 더 안정적으로 가치가 확인된 부분은 다음입니다.

> **점수보다, 사람이 미처 생각하지 못한 확인 질문을 빠르게 만드는 것.**

이 한계를 숨기지 않고 다음 단계에서는 실제 사용자 문서와 독립 평가자를 통해 질문 유용도를 검증할 계획입니다.

## 11. 심사위원에게 보여줄 60초 Demo

**0~10초**

`좋아 보이지만 실제로는 부족한` Sample A 또는 D1 문서를 화면에 붙여넣는다.

**10~25초**

분석 버튼 클릭 → Spinner → Score와 12개 항목 표시.

**25~40초**

Critical Gap과 질문 탭을 보여준다.

강조 문장:

> "요약한 것이 아니라, 원문에 없던 질문을 찾아냈습니다."

**40~55초**

개선 문서 생성 버튼 클릭 → `[정보 필요]`, `[권한 확인 필요]` placeholder가 포함된 문서를 보여준다.

**55~60초**

마무리:

> "인수인계의 문제는 문서가 없는 것만이 아닙니다. 문서는 있지만 중요한 것이 빠져 있는 경우가 더 어렵습니다. 이 AI는 그 빈칸을 찾습니다."

## 12. 제출용 요약문

인수인계 문서는 작성자에게 익숙한 시스템 경로, 권한, 마감시간, 장애대응, 검증방법 등이 자연스럽게 생략되기 쉽습니다. 기존 생성형 AI가 작성된 내용을 요약하는 데 집중한다면, ‘AI 인수인계 구멍 탐지기’는 새 담당자의 관점에서 “이 문서만 받고 내일부터 혼자 일할 수 있는가?”를 검사합니다. 12개 실행정보 영역을 CLEAR/PARTIAL/MISSING으로 진단하고, 빠진 내용을 작성자에게 확인할 질문으로 변환하며, 없는 사실은 추측하지 않고 placeholder가 포함된 개선 문서를 생성합니다. 8개 Synthetic 업무 문서 검증에서 Critical Gap 13개 중 12개를 탐지했으며, 생성된 33개 질문은 합성 검토에서 모두 실행정보 보완에 도움이 되는 질문으로 판단되었습니다. 현재 PoC는 실제 Azure OpenAI와 연결되어 웹에서 직접 체험할 수 있습니다.

## 13. 한 문장 마무리

> **좋은 인수인계는 많이 쓰는 문서가 아니라, 다음 사람이 다시 물어보지 않아도 되는 문서입니다.**

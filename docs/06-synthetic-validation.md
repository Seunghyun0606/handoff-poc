# 06. Synthetic Validation Report

## 1. 목적

실제 인수인계 문서를 확보하기 전, 현재 PoC가 **의도적으로 누락된 업무 정보를 탐지하고 실행 가능한 질문으로 변환할 수 있는지** 검증한다.

이 결과는 실제 사용자 문서 성능이 아니라 **Synthetic Validation**이다. 8개 합성 문서를 먼저 작성하고, AI 실행 전에 각 문서의 Human grade와 의도적으로 부족하게 만든 카테고리(ground truth gap)를 고정한 뒤 Production Azure OpenAI에 입력했다. 이 8건은 결과 확인 전 현재 프롬프트/점수 산식의 재튜닝에 사용하지 않았다.

## 2. Corpus

업무 도메인이 한 종류에 치우치지 않도록 다음 8개 업무를 사용했다.

| ID | 업무 | Human grade |
| --- | --- | --- |
| D1 | 일일 매출자료 공유 | POOR |
| D2 | 급여 인터페이스 전송 | FAIR |
| D3 | 신규 계정 발급 | GOOD |
| D4 | SSL 인증서 갱신 | POOR |
| D5 | 신규 입사자 온보딩 | FAIR |
| D6 | 야간 배치 모니터링 | GOOD |
| D7 | 협력사 세금계산서 처리 | FAIR |
| D8 | 월간 DB 백업 복구 점검 | GOOD |

원문은 `validation/synthetic-corpus.json`에 보관한다.

## 3. 평가 방법

### Score band

- POOR: 0~44
- FAIR: 45~74
- GOOD: 75~95

### Gap Recall

사전에 의도적으로 누락/불충분하게 만든 카테고리 중 AI가 `PARTIAL` 또는 `MISSING`으로 탐지한 비율.

### Gap Precision

AI가 Gap으로 판단한 카테고리 중 사전에 의도적으로 부족하게 만든 카테고리의 비율.

> 이 Precision은 보수적인 지표다. Synthetic ground truth는 **의도적으로 심은 결함**만 기록했기 때문에 AI가 추가로 발견한 실제 유용한 보완사항도 false positive로 계산될 수 있다.

### Critical Recall

핵심 카테고리(`procedure`, `systems_tools`, `access_permissions`, `incident_response`)에 심은 결함 중 AI가 놓치지 않은 비율.

### Question usefulness

생성 질문이 다음 조건을 만족하면 Useful로 판정했다.

1. 문서에 이미 명확히 답이 존재하지 않는다.
2. 답을 알게 되면 인수자의 독립 수행 가능성이 높아진다.
3. 단순 문장 다듬기나 표현 취향이 아니라 실제 업무 실행정보를 요구한다.

이 평가는 단일 검토자에 의한 합성 문서 리뷰이며 독립 사용자 연구가 아니다.

## 6. 주요 관찰

### 6.1 강점 — Critical Gap 탐지

핵심 실행정보 결함 13개 중 12개를 탐지했다. 특히 권한, 장애대응, 절차처럼 업무를 실제로 시작하거나 실패 상황을 복구하는 데 필요한 정보에 강한 신호를 보였다.

D5 신규 입사자 온보딩에서는 의도한 4개 누락(`access_permissions`, `contacts`, `incident_response`, `validation`)을 모두 탐지했고, 각각 다음과 같이 실행 가능한 질문으로 변환했다.

- 필요한 포털 권한과 신청 절차는 무엇인가?
- 반려/장애 문의 담당 팀과 연락 채널은 무엇인가?
- 포털 장애나 이메일 실패 시 재시도·에스컬레이션 절차는 무엇인가?
- 노트북/사원증/교육 등록 완료를 어떤 상태로 검증하는가?

### 6.2 점수는 보조 신호

D2 급여 인터페이스 문서는 Human grade를 FAIR로 두었지만 AI는 95점으로 평가했다. AI가 `오류 시 재처리하거나 운영팀 문의`를 충분한 장애대응으로 판단했기 때문이다. Synthetic ground truth에서는 재처리 실패 이후 에스컬레이션 기준까지 없으므로 `incident_response`를 불충분으로 정의했다.

반대로 D7은 FAIR로 설계했으나 39점으로 낮게 평가했다. AI가 계약관리 시스템 메뉴, 정확한 완료 마감, 산출물 저장위치 등 **의도적으로 심지 않았지만 실제 인수 관점에서는 유용한 추가 확인사항**까지 요구했기 때문이다.

따라서 PoC의 핵심 가치는 단일 점수의 정밀 예측보다는 **누락 후보와 확인 질문을 빠르게 표면화하는 것**으로 보는 것이 적절하다.

### 6.3 추가 Gap이 반드시 오탐은 아님

D6은 의도된 결함을 `follow_up` 하나만 설정했지만 AI는 다음을 추가로 질문했다.

- HR Data팀의 공식 연락 채널
- 전일 HR 확정 변경건수의 조회 위치
- 점검 성공 결과의 기록/전달 위치
- DATA_VALIDATION 오류가 해결되지 않을 때의 에스컬레이션

Ground truth 기준으로는 false positive지만, 실제 인수자의 독립 수행 관점에서는 모두 유용한 보완 질문이다. 따라서 향후 실제 사용자 검증에서는 planted-gap precision뿐 아니라 **Human Useful Question Ratio**를 별도로 측정해야 한다.

## 7. Before → Question → After 사례

### D1 POOR

**Before**

> 매일 오전 매출 자료를 다운받아서 팀에 공유한다. 월말에는 정산 자료도 추가로 만든다. 파일에 문제가 있거나 화면 오류가 나면 담당자에게 문의한다.

**AI 결과**

- Score: 31
- Gap: 10개
- 질문: 8개
- 대표 질문: `업무 수행에 필요한 계정·권한은 무엇이며, 권한이 없을 때 누구에게 어떤 방식으로 신청합니까?`

**After**

개선 문서는 원문에 없는 값을 만들지 않고 아래와 같이 실행 구조와 placeholder를 생성했다.

- `매출 자료 다운로드 시스템: [정보 필요]`
- `필요한 계정 및 권한: [권한 확인 필요]`
- `완료 마감: [시간 확인 필요]`
- `오류 발생 시 재시도 또는 우회 방법: [정보 필요]`
- `문의 담당자: [담당자 확인 필요]`

즉 AI가 답을 지어내는 것이 아니라 **무엇을 더 물어봐야 하는지 구조화**한다.

### D5 FAIR

기존 문서에는 입사자 확인, 노트북/사원증 신청, 교육 링크 발송 절차가 있었지만 권한·담당자·장애대응·검증 기준이 없었다.

AI는 55점과 4개 Gap을 반환했고 개선 문서에 `[권한 확인 필요]`, `[담당자 확인 필요]`, `[확인 화면 또는 상태 기준 필요]`를 배치했다.

### D8 GOOD

완성도가 높은 DB 복구 점검 문서는 95점, Gap 0개, 질문 0개를 반환했다. 개선 문서도 새로운 사실을 추가하지 않고 기존 내용을 목차와 단계 중심으로 재구성했다.

## 8. 가설 판단

### H1. AI가 인수인계 문서의 누락 정보를 찾을 수 있다.

**부분적으로 지지됨.**

- Planted Gap Recall 77.8%
- Critical Gap Recall 92.3%
- 단 1건의 Critical miss 존재

### H2. 요약보다 질문/Gap이 더 직접적인 가치를 제공한다.

**합성 검증에서는 지지 신호가 강함.**

- 33개 질문 생성
- 단일 검토에서 33개 모두 실행정보 보완에 유용
- 점수가 Human grade와 어긋난 D2/D7에서도 질문 자체는 실무적으로 유용했음

### H3. Before/After 차이를 시각적으로 이해할 수 있다.

**Demo 수준에서 지지됨.**

POOR/FAIR 문서의 개선본에서 부족한 정보를 placeholder로 명시해 Before 문서 대비 보완지점이 눈에 띄게 드러났다.

## 9. 한계

1. 실제 조직의 인수인계 문서가 아니라 합성 데이터 8건이다.
2. 문서 작성자와 Useful Question 검토자가 동일하므로 독립적인 사용자 평가가 아니다.
3. planted gap ground truth는 가능한 모든 누락을 exhaustive하게 라벨링한 것이 아니다.
4. Score band 일치율은 75%로, 점수를 절대 품질지표로 사용하기에는 추가 검증이 필요하다.
5. 실제 공모전 제출에서는 이 결과를 `Synthetic Validation`으로 명확히 표기해야 한다.

## 10. 결론

현재 PoC는 **점수를 맞히는 채점기보다, 사람이 지나치기 쉬운 인수인계의 빈칸을 찾아 질문으로 바꾸는 리뷰어**로서 더 강한 가치를 보였다.

따라서 공모전 메시지는 `AI가 문서를 요약한다`가 아니라 다음으로 잡는다.

> **AI가 문서에 적힌 내용을 줄여주는 것이 아니라, 문서에 적히지 않은 내용을 찾아 물어본다.**
